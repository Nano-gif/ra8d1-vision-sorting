# 机械臂控制板重要信息

## 工程定位

- 工程路径：`.\Robotic_Arm_Control`
- 主控：Renesas RA6M5，目标器件 `R7FA6M5BF3CFP`
- 开发环境：Keil MDK + Renesas FSP 6.4.0
- 控制板角色：RS485 / ModbusRTU 从机，固定地址 `1`
- PWM 输出：RA6M5 通过 I2C 控制 PCA9685，由 PCA9685 输出舵机 PWM

## 当前已验证功能

- Debug UART 收发正常，支持 `my_printf()` 打印。
- Debug UART 已支持超时成帧接收，可用于简单命令测试。
- PCA9685 I2C 通信正常，能读写寄存器。
- PCA9685 已验证 50Hz PWM 输出。
- PCA9685 的 0-5 通道已实际控制舵机测试通过。
- 陶晶驰串口屏 HMI UART 收发正常。
- HMI 滑条协议已能控制 0-5 路舵机 PWM。
- Debug 串口、HMI 串口当前都通过统一 `arm_control` 状态层控制 PCA9685。
- HMI 手动页 `基座/工具/工件/相机` 坐标系切换已验证：`A5 34` 能正常到达 RA6M5，基座/工具方向正确，工件/相机预留模式不会误动。

## HMI 舵机滑条协议

HMI 硬件与界面约束：

- 串口屏：陶晶驰 3.2 寸屏。
- 显示分辨率：`320x240`。
- 显示文本优先使用中文，已导入 GB2312 字库。
- 后续界面排版必须按 `320x240` 设计，不要按大尺寸屏幕布局。
- 串口屏组件名可以继续使用 `h0`、`n0`、`b0` 这类短英文/数字命名；屏幕上显示给用户看的文字使用中文。

串口屏发送帧格式：

```text
A5 01 ch us_l us_h FF FF FF
```

字段说明：

| 字段 | 含义 |
|---|---|
| `A5` | 帧头 |
| `01` | 舵机 PWM 设置命令 |
| `ch` | PCA9685 通道，当前只用 `0-5` |
| `us_l` | 脉宽低字节 |
| `us_h` | 脉宽高字节 |
| `FF FF FF` | 陶晶驰串口屏帧尾 |

例子：

```text
A5 01 02 A4 08 FF FF FF
```

表示设置通道 `2` 为 `0x08A4 = 2212us`。

当前 HMI 本地命令：

```text
A5 01 ch us_l us_h FF FF FF   // 设置单路舵机目标 PWM
A5 02 FF FF FF                // 执行当前保存的复位姿态
A5 03 FF FF FF                // 将当前 6 路目标值保存为 Data Flash 复位姿态
A5 04 FF FF FF                // 查询当前关节页目标值并回写屏幕控件
A5 30 axis dir move_mode speed soft step FF FF FF  // 手动页点动/连续运动
A5 31 FF FF FF                // 进入手动页并请求状态同步
A5 32 FF FF FF                // 离开手动页
A5 33 FF FF FF                // 查询手动页状态
A5 34 coord FF FF FF          // 设置手动页坐标系
```

说明：
- `A5 01` 仍然只发送 `ch + us`，角度/百分比只作为屏幕本地显示值，不作为控制协议。
- `A5 02` 由 RA6M5 调用 `arm_action_home(1000ms, HMI来源)`，通过动作插补层平滑复位，不再瞬间跳变。
- `A5 03` 由 RA6M5 调用 `arm_control_save_home_from_current_targets()`，保存到 Data Flash，断电重启后仍会加载上次保存的复位姿态。
- `A5 04` 由 RA6M5 回写关节页 `h0-h5`、`n0-n5`、`n6-n11`，用于切回关节页时同步当前姿态。
- `A5 30` 中的 `move_mode` 只表示运动方式：`0=连续`，`1=步进`，不要把它当作坐标系模式。
- `A5 34` 中的 `coord` 才表示坐标系：`0=基座`，`1=工具`，`2=工件/传送带预留`，`3=相机预留`。
- 工具坐标运动采用常见机械臂控制器里的 Tool Jog 思路：沿当前夹爪自己的 `X/Y/Z_tool` 做微动，固件根据当前 TCP 的偏航、俯仰、旋转换算成基坐标 TCP 目标，再走同一套逆运动学。
- 工件/传送带和相机坐标还没有实物标定，当前只允许 HMI 显示选中状态，不允许实际 jog 运动，避免错误坐标导致机械臂乱动。

## HMI 页面规划 v0.2

页面数量控制为 4 页：

- `首页`：机械臂状态总览，不直接控制机械臂。
- `手动`：实时手动控制机械臂。
- `关节`：单关节调试、标定、维修，包含复位姿态设置。
- `动作`：动作录制、保存、回放。

底部导航固定为：

```text
[首页] [手动] [关节] [动作]
```

所有页面底部导航按钮位置保持一致，当前页面按钮用不同颜色或高亮状态区分。

### 首页

主页设备名为 `机械臂控制终端`，不使用“主控”作为页面或设备名称。
首页只做状态展示，不放实时控制滑条。

320x240 草图：

```text
┌────────────────────────┐
│ 机械臂控制终端          │
│ 状态:就绪  视觉端:在线  │
├────────────────────────┤
│ 当前动作: 00            │
│ 动作步数: 000           │
│ 错误代码: 0             │
│ 当前位置: 复位姿态      │
│                        │
│ [复位]                 │
├────────────────────────┤
│ [首页] [手动] [关节][动作]│
└────────────────────────┘
```

首页控件作用：

| 显示/控件 | 作用 |
|---|---|
| `机械臂控制终端` | 设备名称 |
| `状态` | 显示机械臂当前状态，例如 `就绪`、`忙碌`、`错误`、`复位中`、`回放中` |
| `视觉端` | 显示 vision board 连接状态，例如 `在线`、`离线` |
| `当前动作` | 显示当前执行或待执行的动作编号 |
| `动作步数` | 显示当前动作已执行到第几步 |
| `错误代码` | 显示当前错误码，正常为 `0` |
| `当前位置` | 显示当前是否在 `复位姿态`、`手动位置`、`动作中` 等状态 |
| `[复位]` | 回到预设复位姿态，不等于全部舵机 `1500us` |
| `[首页] [手动] [关节] [动作]` | 固定底部导航标签 |

首页不放 `执行`、`使能`、`急停`：

- `执行` 属于手动页或动作页语义，首页只看状态。
- `使能` 偏底层状态控制，后续可放设置/隐藏命令。
- `急停` 需要完整停机策略和硬件/软件状态配合，未完成前不放在首页，避免语义不清。

### 手动页

手动页用于人工实时控制机械臂。滑条变化后立即进入 `arm_control`，由固件做限幅、速度限制和平滑处理。

```text
┌────────────────────────┐
│ 手动控制          就绪  │
├────────────────────────┤
│ 前后X   000  [──────]   │
│ 左右Y   000  [──────]   │
│ 上下Z   000  [──────]   │
│ 腕俯仰  000  [──────]   │
│ 腕旋转  000  [──────]   │
│ 夹爪    050% [──────]   │
├────────────────────────┤
│ [首页] [手动] [关节][动作]│
└────────────────────────┘
```

手动页控件作用：

| 显示/控件 | 作用 |
|---|---|
| `前后X` | 末端沿基坐标 X 方向实时移动控制 |
| `左右Y` | 末端沿基坐标 Y 方向实时移动控制 |
| `上下Z` | 末端沿基坐标 Z 方向实时移动控制 |
| `腕俯仰` | 末端手腕俯仰姿态实时控制 |
| `腕旋转` | 末端腕部旋转实时控制 |
| `夹爪` | 夹爪开合百分比实时控制 |

手动页第一阶段可以先显示界面，不急于启用 X/Y/Z 联动控制；等关节安全范围和角度映射完成后再启用。

### 关节页

关节页用于单关节调试、标定和复位姿态设置。

```text
┌────────────────────────┐
│ 关节调试          安全  │
├────────────────────────┤
│ 腰    1500  000° [────] │
│ 肩    1500  待测 [────] │
│ 肘    1500  待测 [────] │
│ 腕俯  1500  平行 [────] │
│ 腕旋  1500  待测 [────] │
│ 夹爪  1500  闭合 [────] │
├────────────────────────┤
│ [复位] [设为复位]       │
│ [首页] [手动] [关节][动作]│
└────────────────────────┘
```

关节页控件作用：

| 显示/控件 | 作用 |
|---|---|
| 六个关节滑条 | 单独调整每个舵机，用于标定和维修 |
| `us` 数值 | 显示当前 PWM 高电平，标定时必须可见 |
| 角度/状态 | 显示角度、待测、平行、闭合等状态 |
| `[复位]` | 回到当前保存的复位姿态 |
| `[设为复位]` | 将当前 6 个关节值保存为复位姿态 |

复位姿态是一组固定的 6 关节目标值，后续 `首页复位`、Modbus `home` 命令、动作结束后的自动复位都使用同一组复位姿态。

当前临时复位姿态 v0.1：

```text
Base  / h0 / PWM0 = 1500us
Shldr / h1 / PWM1 = 500us
Elbow / h2 / PWM2 = 500us
Pitch / h3 / PWM3 = 2443us
Roll  / h4 / PWM4 = 1457us
Grip  / h5 / PWM5 = 500us
```

HMI 关节页前初始化事件不要再下发上述 6 路固定 PWM，否则切回关节页时会覆盖刚刚调好的姿态。新的同步方式是进入关节页时发送 `A5 04 FF FF FF`，由 RA6M5 回写当前姿态到滑条、us 数值和角度/百分比控件。正式复位流程已由 RA6M5 保存并执行：`复位` 按钮发送 `A5 02 FF FF FF`，`设为复位` 按钮发送 `A5 03 FF FF FF`。当前 `设为复位` 会保存到 RA6M5 Data Flash，断电重启后仍会加载。

复位姿态 Flash 存储说明：
- 只保存 6 路复位脉宽，单位 `us`。
- Data Flash 使用末尾两个 `64B` 块做冗余槽，保存时轮流写入。
- 每条记录包含标识、版本、序号、6 路脉宽和校验值；上电时选择序号最新且校验通过的记录。
- 如果两个槽都没有合法记录，固件使用下面这组默认复位姿态。

关节页不要一直定时轮询 `A5 04`，否则 MCU 持续回写 `h0-h5` 会导致滑条闪烁、拖动卡顿。当前推荐做法：

```text
关节页前初始化事件:
tm0.en=0
printh A5 04 FF FF FF

复位按钮弹起事件:
printh A5 02 FF FF FF
tm0.tim=1100
tm0.en=1

tm0 定时事件:
printh A5 04 FF FF FF
tm0.en=0
```

其中 `tm0.tim=1100` 是配合当前 `1000ms` 平滑复位时长预留的查询延时。

### 动作页

动作页用于录制和回放完整机械臂动作。动作不按每个关节分别录制，而是记录一组组完整机械臂姿态关键点。

```text
┌────────────────────────┐
│ 动作管理          空闲  │
├────────────────────────┤
│ 编号:00    步数:000     │
│ 速度:100%  间隔:050ms   │
│                        │
│ [录制]    [加一步]      │
│ [播放]    [停止]        │
│ [上一组]  [下一组]      │
│ [清空]    [保存]        │
├────────────────────────┤
│ [首页] [手动] [关节][动作]│
└────────────────────────┘
```

动作录制流程：

1. 在动作页选择 `编号`。
2. 点击 `[录制]`，系统进入录制状态。
3. 切到 `手动` 页或 `关节` 页，把机械臂移动到一个目标姿态。
4. 回到动作页点击 `[加一步]`，保存当前 6 个关节值、夹爪状态和本步持续时间。
5. 重复第 3-4 步，直到完成“抓取、搬运、放下、离开”的全过程。
6. `[加一步]`、`[删除最后一步]`、`[清空]` 成功后，当前 RAM 动作会自动同步写入 RA6M5 Data Flash。
7. 点击 `[播放]` 时，机械臂按关键点顺序执行。
8. 播放完成后，系统自动执行 `复位姿态`，然后状态回到 `就绪`。

动作页本地 HMI 命令：

```text
A5 10 duration_l duration_h FF FF FF  // 加一步，保存当前 6 路目标和本步时间到 RAM
A5 11 FF FF FF                        // 删除最后一步
A5 12 FF FF FF                        // 清空当前 RAM 动作
A5 13 FF FF FF                        // 播放当前 RAM 动作
A5 14 FF FF FF                        // 停止播放
A5 15 FF FF FF                        // 查询动作页状态
```

动作 Flash 存储说明：

- 动作录制先修改 RAM 动作槽，`加一步`、`删除最后一步`、`清空` 成功后立即同步到 Data Flash。
- 第一版只有一个动作槽：`0 = NG分拣`。
- 每个关键帧保存 `6路舵机目标PWM(us) + 本步动作时间(ms)`。
- 最多 `20` 个关键帧。
- Data Flash 使用复位姿态前面的两个 `384B` 冗余槽保存动作：
  - action slot0：`0x08001C80 - 0x08001DFF`
  - action slot1：`0x08001E00 - 0x08001F7F`
  - home slot0：`0x08001F80 - 0x08001FBF`
  - home slot1：`0x08001FC0 - 0x08001FFF`
- 动作记录包含标识、版本、序号、步数、关键帧数据和校验值；上电时选择序号最新且校验通过的记录。
- `A5 12` 和 Modbus `control_command=8` 会清空 RAM 动作，并同步保存“0 步动作”到 Flash；下次上电后动作槽仍为空。

缺陷品分拣工作链路：

```text
视觉端检测到缺陷
-> 根据传送带速度和机械臂距离等待/同步
-> vision board 通过 Modbus 下发播放动作命令
-> 机械臂状态变为 忙碌
-> 执行抓取动作
-> 放入缺陷盒
-> 自动执行复位姿态
-> 状态回到 就绪
-> 上位机/vision board 轮询到就绪后进入下一轮检测
```

### vision board 与 HMI 数据链路原则

vision board 不直接控制串口屏再由串口屏转控机械臂。推荐链路为：

```text
vision board -> RS485/ModbusRTU -> RA6M5 arm_control -> 舵机/PCA9685
                                              └──────-> HMI 状态显示同步
```

也就是说，vision board 可以下发 `播放动作`、`目标位置`、`模式切换` 等命令给 RA6M5；RA6M5 统一进入 `arm_control` 后执行，并同步刷新 HMI 显示。

vision board 任务级动作命令：

```text
远程维护/调试时，强制同步当前 RAM 动作到 Data Flash，可选：
10H slave=1 start=0x00F0 count=3 values=[7, 0, command_seq++]

执行已保存/已加载的 NG 分拣动作：
10H slave=1 start=0x00F0 count=3 values=[5, 0, command_seq++]
```

正常 HMI 动作录制不需要单独保存命令；`加一步`、`删除最后一步`、`清空` 成功后已经自动同步到 Flash。
vision board 下发播放、清空、强制同步等 Modbus 命令后，必须读 `04H slave=1 start=0x0009 count=3` 确认 `last_command_seq/code/result`，不能只看写寄存器响应。

## 机械臂坐标系 v0.3

本工程机械臂坐标系采用右手坐标系。所有旋转关节的正方向均按右手定则定义：右手大拇指指向该关节旋转轴正方向，四指弯曲方向为关节角正方向。

基坐标系 `base`：

- 原点：J1/Base 腰关节旋转中心。
- `+Z_base`：从底座竖直向上。
- `+X_base`：机械臂中位姿态下，末端伸出的水平方向。
- `+Y_base`：由右手系确定，满足 `X_base x Y_base = Z_base`，等价于 `Y_base = Z_base x X_base`。

俯视图：

```text
                 +X_base 机械臂正前方
                         ↑
                         |
        +Y_base  ←--------O--------→  -Y_base
                         |
                         ↓
                    -X_base

O：J1/Base 腰关节旋转中心
+Z_base：从底座竖直向上，也就是从纸面朝外
```

不要在文档中单独使用“面对 +X”描述坐标方向，必须写清楚观察方向。等价观察描述为：

```text
从原点沿 +X_base 正方向看去，画面左侧为 +Y_base。
从 +X_base 端看回原点时，画面右侧为 +Y_base。
```

末端工具坐标系 `tool`：

- `TCP`：Tool Center Point，当前夹爪真正夹住物体时，物体中心大概所在的位置。
- `+X_tool`：从腕部/夹爪根部指向被夹物体的方向，也就是夹爪伸出去抓东西的方向。
- `+Y_tool`：夹爪两指张开/闭合的宽度方向。Roll 为 `0deg` 时，`+Y_tool` 作为夹爪横向参考方向。
- `+Z_tool`：由右手系确定，满足 `X_tool x Y_tool = Z_tool`。
- Wrist Roll/J5 是绕 `+X_tool` 的旋转；`+Y_tool` 转向 `+Z_tool` 为 Roll 正方向。

工具坐标系示意：

```text
从机械臂侧面理解：

腕部/夹爪根部 -----> TCP/物体中心
                  +X_tool

从夹爪正面看：

        +Z_tool
           ↑
           |
   -Y_tool O +Y_tool     O：TCP
           |
           ↓
        -Z_tool

+X_tool 垂直于这个观察平面，沿夹爪伸向物体的方向。
Roll 正方向是绕 +X_tool 旋转，按右手定则为 +Y_tool 转向 +Z_tool。
```

当物体被传送到基座 `+X_base` 轴附近、`Y_base` 接近 `0` 时，夹爪通常会让 `+X_tool` 指向物体中心。后续视觉端如果识别到物体有平面旋转角，不应直接用图像角度驱动舵机，而应先转换为工具坐标或基坐标下的 `Roll_target_deg`。

### 手动模式与关节模式区别

本工程至少保留两类人工操作模式：

| 模式 | 控制对象 | 现象 | 用途 |
|---|---|---|---|
| 关节模式 | 单个关节 J1-J6 | 只要求对应关节运动，TCP 会跟着画弧线 | 标定、维修、找安全范围、设置复位姿态 |
| 基座模式 | TCP 在 `base` 坐标系下的位置/姿态 | 为了保持 TCP 位置或姿态，肩、肘、腕可能联动 | 手动抓取、示教动作、接近实际作业 |
| 工具模式 | TCP 沿 `tool` 坐标系移动或绕工具轴旋转 | 运动方向跟随夹爪自身朝向 | 夹爪对准物体后，沿夹爪方向前进/后退、微调抓取 |
| 工件模式 | TCP 沿工装/传送带坐标系移动 | 暂时预留，等传送带实物框架完成后标定 | 缺陷品分拣、固定工位抓取 |
| 相机模式 | 图像/相机坐标调试 | 暂时预留，等相机和传送带安装完成后标定 | 视觉抓取、像素到实际坐标转换 |

注意：

- 在关节页点击 `Pitch/腕俯仰`，语义是直接动 J4 腕俯仰关节，TCP 位置会跟着改变。
- 在手动页基座模式点击 `俯仰`，语义是改变 TCP 末端姿态。为了让 TCP 尽量保持目标位置，肩关节、肘关节、腕关节联动是正常现象。
- 如果只是想单独验证某个舵机或某个关节，不要用手动页 TCP 控制，应使用关节页。
- 如果是实际抓取、示教动作、后续 Modbus/vision board 控制，应逐步使用 TCP 目标位姿控制。
- 手动页坐标系选择和连续/步进选择是两件事：坐标系决定“往哪个参考系方向动”，连续/步进决定“按住一直动还是点一下动一步”。这也是常见机械臂示教器的设计方式，后续 Modbus/PC 上位机也应按这个思路拆开命令字段。

### 后续视觉抓取坐标链路

当前先不标定相机坐标系和工件/传送带坐标系，只保留最终链路：

```text
相机像素坐标
-> 相机坐标/工作台坐标
-> 机械臂基坐标 base
-> TCP 目标位置和工具姿态
-> 逆运动学求关节角
-> 舵机 PWM
-> 平滑轨迹执行
```

后续传送带实物框架完成后，需要再测量并记录：

- 传送带运动方向相对 `+X_base` 的夹角。
- 传送带中心线相对 J1/Base 原点的 `X/Y/Z` 偏移。
- 相机安装高度、视野方向、像素到毫米的标定关系。
- 缺陷物品到达抓取点的时间补偿，和传送带速度关联。

关节角度正负按机械臂坐标系和各关节旋转轴定义，不直接等同于 PWM 脉宽增减。HMI 滑条命令仍只发送 `ch + us` 给 RA6M5，角度仅作为屏幕调试显示；后续正式运动学应由 RA6M5 的 `arm_control` 统一换算。

| 关节 | 名称 | PWM 通道 | 角度定义/标定点 | us 增大方向 | us 减小方向 | 安全/调试范围 |
|---|---|---:|---|---|---|---|
| J1 | Base/腰关节 | 0 | `500us=-90deg`，`1500us=0deg`，`2500us=+90deg` | 从上方俯视底座为逆时针，角度增大 | 从上方俯视底座为顺时针，角度减小 | `500-2500us` |
| J2 | Shldr/肩关节 | 1 | `2327us≈0deg` 水平向 `+X_base`，`1312us≈+90deg` 竖直向 `+Z_base`，`500us` 为复位候选点 | 大臂下放，角度减小 | 大臂上抬/回收，角度增大 | 机械允许 `500-2327us`，HMI 上限可保守用 `2300us` |
| J3 | Elbow/肘关节 | 2 | 小臂相对大臂角：`500us≈-90deg`，`1500us≈0deg`，`2356us≈+90deg` | 小臂向 `-X_base` 侧转，角度增大 | 小臂向 `+X_base` 侧转，角度减小 | `500-2356us` |
| J4 | Pitch/腕俯仰 | 3 | 手掌/夹爪相对小臂角：`1500us=0deg`，`2443us≈-90deg` | 手腕向前下俯，角度变负 | 手腕上仰，角度增大 | 作业建议 `1500-2443us`，机械可测到约 `2500us` |
| J5 | Roll/腕旋转 | 4 | 绕 `+X_tool`：`500us≈-90deg`，`1457us=0deg`，`2415us≈+90deg` | `+Y_tool` 转向 `+Z_tool`，Roll 增大 | `+Z_tool` 转向 `+Y_tool`，Roll 减小 | `500-2415us` |
| J6 | Grip/夹爪 | 5 | 位置控制，不按关节角参与当前运动学 | 夹爪闭合 | 夹爪张开 | `500-1500us` |

J1 Base 实测记录：

- 观察基准：从上方俯视底座转盘，也就是沿 `+Z_base` 反方向看向原点。
- 正方向：从 `+X_base` 转向 `+Y_base`，俯视图中为逆时针。
- `500us` 对应约 `-90deg`。
- `1500us` 对应约 `0deg`。
- `2500us` 对应约 `+90deg`。
- 临时线性映射：`angle_deg = (pulse_us - 1500) * 0.09`。

J2 Shldr 实测记录：

- J2 对应 PCA9685 `PWM1`，是大臂相对底座的俯仰关节。
- `2327us` 时，大臂接近水平向 `+X_base`，定义为约 `0deg`；HMI 为保守起见可把最大值设为 `2300us`。
- `1312us` 时，大臂接近竖直向 `+Z_base`，定义为约 `+90deg`。
- `500us` 用户确认机械上可接受，保留为复位候选点。
- `us` 增大时大臂下放，角度减小；`us` 减小时大臂上抬/回收，角度增大。
- `1500-2327us` 区间肩关节扭矩压力较大，动作播放时需要插补、限速，并尽量让肘关节/腕关节配合减小负载。
- 当前 HMI 显示公式建议仍以实测 `2327us` 为 `0deg`：`angle = (2327 - us) * 90 / 1015`；滑条最大值用 `2300us` 时显示约 `2deg` 属正常。

J3 Elbow 实测记录：

- J3 对应 PCA9685 `PWM2`，是小臂相对大臂的关节角，不是小臂相对地面的角度。
- 测试基准：大臂保持竖直，近似平行 `+Z_base`。
- `500us` 时小臂接近 `+X_base` 方向，定义为约 `-90deg`。
- `1500us` 时小臂接近 `+Z_base` 方向，与大臂近似同向，定义为 `0deg`。
- `2356us` 时小臂接近 `-X_base` 方向，定义为约 `+90deg`。
- 建议 HMI 采用分段显示：`500-1500us` 按 `-90deg` 到 `0deg`，`1500-2356us` 按 `0deg` 到 `+90deg`。
- 运动学中，小臂相对地面的角度应由肩关节角和肘关节相对角共同决定，不要把 J3 显示角直接当成地面角。

J4 Pitch 实测记录：

- J4 对应 PCA9685 `PWM3`，是手掌/夹爪相对小臂的俯仰角。
- 测试基准：小臂保持竖直，近似平行 `+Z_base`。
- `1500us` 时手掌/夹爪接近 `+Z_base`，与小臂近似同向，定义为 `0deg`。
- `2443us` 左右时手掌/夹爪接近 `+X_base`，定义为约 `-90deg`。
- `us` 增大时手腕向前下俯，角度变负；`us` 减小时手腕上仰，角度增大。
- 建议 HMI 显示公式：`angle = -(us - 1500) * 90 / 943`。
- 若 HMI 最大值设为 `2500us`，会显示到约 `-95deg`；正式作业可把软件上限限制到 `2443us`。

J5 Roll 实测记录：

- J5 对应 PCA9685 `PWM4`，是末端绕 `+X_tool` 的旋转。
- 标准正方向：右手大拇指指向 `+X_tool`，四指弯曲方向为正方向，即 `+Y_tool` 转向 `+Z_tool`。
- 观察方向必须写清楚：从 `+X_tool` 端面对夹爪正面，看向 `-X_tool` 方向时，Roll 正方向看起来为逆时针。
- `1457us` 时手掌与 `XY_base` 平面平行，定义为 `0deg`。
- `2415us` 时接近 `+90deg`，即 `+Y_tool` 转向 `+Z_tool`。
- `500us` 时接近 `-90deg`，即 `+Z_tool` 转向 `+Y_tool`。
- `us` 增大时 Roll 角度增大；`us` 减小时 Roll 角度减小。
- 建议 HMI 采用分段显示：`500-1457us` 按 `-90deg` 到 `0deg`，`1457-2415us` 按 `0deg` 到 `+90deg`。
- HMI 分段公式：`500-1457us` 分母为 `957`；`1457-2415us` 分母为 `958`。
- 后续视觉端不要直接下发相机图像角度；PC/vision board 需要先把物体偏转角转换为机器人坐标系或工具坐标系下的 `Roll_target_deg`，再通过 Modbus 下发给 RA6M5。

J6 Grip 实测记录：

- J6 是末端夹爪，对应 PCA9685 `PWM5`。
- `us` 减小时夹爪张开，`500us` 左右张开最大。
- `us` 增大时夹爪闭合，`1500us` 左右接近完全闭合。
- 当前夹爪可用 PWM 高电平范围记录为 `500-1500us`。
- 普通舵机夹爪是位置控制，不是力矩控制；夹持大物体时不要用过小闭合目标强行加力，否则容易堵转、掉压、发热，甚至夹住一会后自动松开。

## 机械臂几何参数 v0.1

以下参数为当前实物机械臂的第一版运动学测量基准，单位统一为 `mm`。后续做手动页 `X/Y/Z/俯仰/旋转/夹爪` 联动控制和 IK 时，优先使用这些定义，不要随意改变变量含义。

| 参数 | 数值 | 定义 |
|---|---:|---|
| `Hbase` | `80.0mm` | 当前安装状态下，地面/桌面参考平面到 J1 腰关节顶部水平转盘中心平面的高度。这个是安装高度，后续机械臂放到地面或传送带旁时可能变化。 |
| `L0` | `12.0mm` | J1 腰关节顶部水平转盘中心平面到 J2 肩关节转轴中心的垂直高度差。 |
| `D0` | `+8.8mm` | J1 腰关节竖直旋转轴到 J2 肩关节转轴中心的水平偏移，正号表示沿 `+X_base` 方向偏移。 |
| `L1` | `103.2mm` | J2 肩关节转轴中心到 J3 肘关节转轴中心，中心到中心距离，也就是大臂长度。 |
| `L2` | `127.2mm` | J3 肘关节转轴中心到 J4 腕俯仰转轴中心，中心到中心距离，也就是小臂长度。 |
| `L3a` | `64.0mm` | J4 腕俯仰转轴中心到 J5 腕旋转轴中心的距离。 |
| `L3b` | `100.0mm` | J5 腕旋转轴中心到夹爪 TCP 的距离。TCP 按夹爪半开/典型夹取状态下物体被夹住的中心点定义。 |
| `L3_total` | `164.0mm` | `L3a + L3b`，第一版 IK 可先当作 J4 腕俯仰转轴中心到 TCP 的末端长度。 |
| `Grip_open_width` | `55.0mm` | 夹爪在 `500us` 附近最大张开时的开口宽度。 |
| `Grip_close_width` | `0.0mm` | 夹爪可直接闭合，按接近 `0mm` 记录。 |

说明：

- `Hbase` 不是机械臂连杆长度，而是安装高度/环境参数；后续抓传送带上的物体时，应结合传送带平面高度重新建立世界坐标到机械臂基坐标的关系。
- 第一版 IK 最少需要 `L0`、`D0`、`L1`、`L2`、`L3_total`。
- `TCP` 是 Tool Center Point，即末端工具中心点。对当前夹爪来说，TCP 指夹住物体时物体中心大概所在的位置，不是夹爪外壳边缘，也不是完全张开时爪尖末端。

## 架构约束

- 所有控制来源，包括 Debug 命令、HMI、后续 Modbus，都必须进入统一 `arm_control` 状态/命令层。
- 各模块不允许直接抢 PCA9685。
- PCA9685 输出必须以 `servo_target_us` / `servo_current_us` 模型为中心。
- 后续将 HMI 从“直接显示 us”逐步升级为“关节名 + 角度/百分比 + 限位 + 当前状态”。
